# Security Audit — quran-tracker

**Tanggal:** 2026-10-26
**Commit saat audit:** `12517fa` (branch `main`)
**Metode:** review statis seluruh `src/`, `scripts/`, `drizzle/`, dan konfigurasi; `pnpm audit`; verifikasi dinamis pada instance lokal sekali-pakai (`next build` + `next start`, DB SQLite sementara, kredensial buatan). Tidak ada traffic ke sistem eksternal dan tidak ada akses ke database produksi.

## Yang diperiksa dan bersih

Dicek dan tidak ditemukan masalah: SQL injection (tidak ada raw SQL/`.execute()`; semua query lewat Drizzle builder + Zod), XSS (tidak ada `dangerouslySetInnerHTML`/`innerHTML`/`eval`; input dirender sebagai teks React), SSRF (tidak ada fetch keluar dari `src/`; `remotePatterns` kosong → optimizer menolak URL eksternal), path traversal pada `/_next/image`, hardcoded secret, credential ter-commit (seluruh history git), secret di bundle client, insecure file upload (tidak ada upload), session fixation (token baru tiap login), user enumeration (401 seragam + dummy hash argon2), algoritma password lemah (argon2id), dan bypass middleware lewat path confusion (`//`, `/./`, `%61`, `;.css`, `..`).

## Detail perbaikan

### F-01 + F-02 — Pembatasan body dan array

- `src/lib/http/body-limit.ts`: `MAX_BODY_BYTES = 64 KB`, dicek dari `Content-Length` **dan** dihitung ulang saat stream dibaca (menutup chunked tanpa Content-Length).
- Semua handler mutasi memakai `guardAndReadJson()`, bukan `req.json()`.
- `src/lib/tracker/validation.ts`: `itemsWithinLimit()` memeriksa panjang array **sebelum** Zod menyentuh elemen.

Bukti sebelum/sesudah (instance lokal, 200k item tidak valid):

| | Sebelum | Sesudah |
|---|---|---|
| Status | 400 setelah 75 ms | 413 dalam 9–46 ms |
| RSS 3 request | 208 → 567 → 631 → 817 MB (tidak turun) | 165 → 181 → 180 → 179 MB (datar) |

### F-03 — Kunci rate limit

- Kunci dari `x-nf-client-connection-ip` (header platform), lalu hop terakhir `x-forwarded-for`. `x-real-ip` tidak dipakai sama sekali.
- `MAX_KEYS = 10_000` + sweep, mencegah pertumbuhan Map permanen.
- Verifikasi: 6 percobaan dengan `x-nf-client-connection-ip` sama → `429` walau `x-real-ip` diganti.

### F-04 + F-12 — Header & metadata

- `next.config.ts`: CSP, `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, COOP, HSTS; `poweredByHeader: false`.
- CSP memakai `'unsafe-inline'` untuk script karena Next menyuntikkan inline bootstrap; nilai sebenarnya ada pada `frame-ancestors`/`base-uri`/`object-src`. Nonce per-request adalah pekerjaan lanjutan.
- Logout memakai `Location: /login` relatif. Middleware memakai `req.nextUrl.origin` karena `NextResponse.redirect` menuntut URL absolut.

### F-07 — Invarian jangkar `sabaq`

`src/lib/tracker/sabaq-anchor.ts`: `sabaq` bertanggal sebelum `sabaq` pertama sebuah halaman ditolak (`400`). Log yang sedang diedit dikecualikan agar koreksi tanggal log pertama tetap mungkin. `sabqi`/`manzil` tidak dibatasi.

### F-08 — CSRF

- `Content-Type` wajib `application/json` (415) dan `Origin` harus cocok dengan `Host` (403).
- **Ditemukan saat walk-through browser:** versi pertama membandingkan `Origin` dengan origin `req.url`, yang menolak login sah. Diperbaiki memakai header `Host`; regresi ditutup test.
- Logout (`<form method="post">` tanpa body JSON) hanya menjalankan cek same-origin.

### F-10 + F-11 — Sesi & env

- `purgeExpiredSessions()` dipanggil saat login; `MAX_SESSIONS_PER_USER = 5` membatasi sesi aktif. Verifikasi: 8 login → 5 baris.
- `SESSION_SECRET` dihapus dari schema env, `.env.example`, dan README karena tidak pernah dibaca.

### F-13 — Otomasi

`.github/workflows/ci.yml` (audit + lint + test + build) dan `.github/dependabot.yml`. Gate audit diset pada `--audit-level=critical` karena PostCSS (build-time, transitif dari Next) masih dilaporkan `high`; lihat F-09.

## Area yang belum dapat diverifikasi

- **Header IP di produksi Netlify.** Apakah `x-nf-client-connection-ip` selalu diisi dan tidak dapat dipalsukan klien di konteks deploy ini. Perlu satu request uji ke deploy preview.
- **Batas memori & konkurensi function Netlify** yang sebenarnya, menentukan berapa request untuk OOM.
- **`sharp@0.35.5` di Linux/Netlify.** Terverifikasi di mesin lokal (Windows).
- **Cakupan advisory PostCSS** pada pipeline build Netlify (diasumsikan tidak memproses CSS dari sumber eksternal).
- **`local.db`** di repo (stale) tidak dibuka.

## Rencana lanjutan

1. **Multi-user (F-06).** Perlu `ALTER TABLE` untuk `user_id` di `sessions_log`, `goals`, `rest_days`, dan `settings`; filter kepemilikan di setiap query; unique index per pengguna. **Penting:** `getCachedStatuses()` menyimpan seluruh tabel `memorization_status` dalam satu cache ber-tag global tanpa dimensi pengguna — harus diberi dimensi pengguna atau dihapus sebelum multi-user aktif, jika tidak akan menjadi kebocoran lintas pengguna.
2. **CSP nonce** per-request untuk menghapus `'unsafe-inline'` pada `script-src`.
3. **Store rate limit bersama** (DB/Upstash) agar tidak best-effort di multi-instance.
4. **Upgrade PostCSS** mengikuti rilis Next berikutnya.
